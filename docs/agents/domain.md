# Domain documentation

This is a single-context project. Read CONTEXT.md for product terminology before
exploring or implementing. Consult relevant docs/adr decisions before architectural
changes. PROJECT.md is the product contract; WORKFLOW.md defines task ordering,
acceptance, reviews, and commits.

Use the glossary's names in specifications, tickets, interfaces, and test names.
Surface contradictions with existing ADRs before making a conflicting change.
